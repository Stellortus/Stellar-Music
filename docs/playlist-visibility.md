# 歌单可见性接口约定

客户端复用现有歌单 PUT 接口和 `UpdatePlaylistRequest.public`，不需要新增切换接口。更新请求始终显式发送 `public`，包括 `false`；重命名也显式保留已有状态。

创建弹窗默认私有，POST 创建请求也始终发送所选 `public`。搜索接口为 `GET /playlists/search`，搜索内容使用查询参数 `key`，返回 `List<Playlist>`。搜索结果不显示管理菜单；服务端仍需按访问权限筛选结果，不能泄露其他用户的私有歌单。

公共库 1.1.0 的 `Playlist` 包含 `public`，但 `PlaylistDetail` 不包含。详情页重命名前暂通过列表查询当前值，读取不到则停止提交。建议后续公共库和后端详情响应补齐 `public`，移除此额外查询；详情页目前不提供可见性设置。

后端源码不在当前工作区，以下行为尚未联调确认：

- 列表返回当前用户自己的私有歌单，使用户设为私有后仍可再次修改。
- 私有歌单只允许所有者读取，其他用户不能通过详情或曲目接口访问。
- 修改可见性必须校验所有者身份；客户端隐藏菜单不能代替服务端授权。

客户端不对服务端返回的列表做权限过滤。若服务端未落实上述行为，需要在服务端补齐。
